# 一亩三分地本地工具

[![CI](https://github.com/mofan552/1point3acres-toolkit/actions/workflows/consistency.yml/badge.svg)](https://github.com/mofan552/1point3acres-toolkit/actions/workflows/consistency.yml)

每天自动帮你完成一亩三分地（1point3acres）的 **签到** 和 **每日答题**。每天稳拿 2 个大米，连续签到不断档，你什么都不用做。

全程在 **你自己的电脑** 上、用 **你自己的登录** 完成，不经过任何第三方服务器，不用打码平台。支持 **macOS 和 Windows**，只需要 **Chrome + Python 3.12**。

签到答题之外，它还能采集面经、离线搜索、发帖回复，并能作为 MCP 服务接给 Claude Code、Codex 这类 AI 助手用。这些是附加功能，不装不影响签到答题。

> 仓库地址：<https://github.com/mofan552/1point3acres-toolkit>。这是唯一维护中的仓库，旧仓库已停止更新。本文讲原理；具体命令、参数和排错步骤在 [使用说明](outputs/一亩三分地本地工具/README.md)。

![今日任务：签到领奖已完成，每日答题已完成](docs/today-tasks.svg)

打开「我的积分」，每天都有两条 +1 大米的记录：一条「签到奖励」，一条「每日答题」。

这两张图就是工具每天的全部目标。它不会做别的事：不发帖、不回复、不点赞、不写日记（除非你明确打开随机心情，见 [签到](#签到)）。

## 2. 三分钟看懂它怎么工作

一句话：**你的电脑每 10 分钟醒来问一次「今天签了吗」，没签就开一个专用的 Chrome，用你自己的登录，像人一样点按钮，点完再去积分页确认大米真的到账。**

![总览：一次自动运行经过的九步](docs/overview.svg)

逐步解释：

1. **系统计划触发。** macOS 用 launchd，Windows 用任务计划程序，每 10 分钟把工具叫醒一次。
2. **它只是一条 Python 命令。** 入口脚本找到虚拟环境里的 Python，把参数交给命令行模块，再交给每日任务模块。
3. **先离线判断，不开浏览器。** 读本机数据库：还没到你设定的时间？今天两项都已经确认到账？是的话直接退出，这次什么都不做。绝大多数触发都停在这一步，所以每 10 分钟跑一次也不费资源。
4. **启动专用 Chrome。** 和你平时用的浏览器完全隔离，见下图。
5. **签到。** 打开签到页，点「没心情」，点「提交签到」。细节见 [签到](#签到)。
6. **答题。** 读出今天的题目和选项，和题库比对，命中就点对应选项、点「提交答案」。细节见 [答题](#答题)。
7. **核对到账。** 打开积分流水页，确认当天有「签到奖励 +1」和「每日答题 +1」两条记录，而且是你账号名下的。细节见 [核对](#核对)。
8. **记录在本机。** 这次运行的完整结果写进本机数据库，以后可以离线查。
9. **报告结果。** 输出一段 JSON，整体状态是 `complete`、`needs_attention` 或 `failed` 三者之一。

### 专用 Chrome 是什么

工具不会动你平时用的浏览器。它用本机安装的 Chrome 程序，但指定一个独立的配置目录，里面只有这个论坛的登录状态。它通过 Chrome 的调试协议（CDP）在页面里执行脚本、监听网络请求，调试端口只监听本机、端口随机，外面连不进来。

![专用 Chrome：和你平时用的浏览器完全隔离](docs/browser-isolation.svg)

三个配套机制：文件锁保证同一时刻只有一个任务在用它；看门狗线程保证一次运行不会无限挂着；地址白名单保证它只会打开论坛自己的域名。

## 3. 自动签到是怎么做的

![自动签到：五个步骤](docs/checkin-flow.svg)

**第 1 步，打开签到页。** 打开前先确认登录还在不在，不在就自动恢复（见下面「登录是怎么自动恢复的」）。

**第 2 步，选心情。** 签到页要求选一个心情。工具默认点「没心情」。选这个的好处是：站点不会要求你写「今日说说」，你的主页不会多出任何一条记录。

**第 3 步，点「提交签到」。** 只点一次。如果按钮还没就绪（页面没加载完、被禁用），报 `button_not_ready` 退出，留给下一次计划再来，不会硬点。

**第 4 步，等站点真实回应。** 点完按钮不算数，工具会盯着浏览器的网络请求，等到站点的签到接口真的返回了才往下走，最多等 45 秒。快超时时会自动尝试一次人机验证，防止是验证挡住了。

**第 5 步，核对到账。** 打开积分流水页，看当天有没有一条「签到奖励」、大米 +1、属于你 uid 的记录。有，这一项才算 `reward_verified`。

### 登录是怎么自动恢复的

每次运行开头都先调用站点的身份接口问一句「还登录着吗」。登录过期了，就打开站点自己的登录页，把系统保管的用户名密码填进去，等 Cloudflare 的人机验证（Turnstile）通过后点登录。登录成功后再核对一次身份：站点返回的用户名和 uid 必须和你配置里写的一致，不一致就报 `unexpected_account` 停下，绝不用别人的账号操作。

![登录是怎么自动恢复的](docs/login-flow.svg)

### 关于「今日心情 / 说说」

签到页除了心情还能写一句「说说」，发出去会变成你主页上的一条公开记录。工具 **默认什么都不写**。

如果你觉得每天一格「没心情」太像机器，可以在账号配置里显式打开随机心情（字段名 `checkin_mood_random`，见上面签到图右侧）：

- 从站点提供的 10 种心情里按权重抽一个：开心 17、疲惫 15、无聊 14、慵懒 13、奋斗 12、没心情 11、郁闷 9、难过 5、衰 3、生气 1。日常心情多、强烈情绪少，看起来像真人。
- 昨天的心情有 25% 的概率延续到今天，所以会出现连着几天「疲惫」这种自然的连续。
- 从随仓库分发的 321 句中性短句里（按心情分组）抽一句填进「说说」，最近 30 天用过的句子不重复。
- 心情和句子都记进本机运行历史。

**打开后每天会以你的名义在主页发一句话。** 这是你的选择，工具不替你决定。不打开，行为和以前完全一样。奖励核验的规则不变。

## 4. 自动答题是怎么做的

![自动答题：读题、查题库、作答、核对到账、学习](docs/quiz-flow.svg)

**第 1 步，读题。** 工具不去截图识别，而是直接调用站点自己的题目接口，拿到今天的题目原文和全部选项。都是纯文本，没有歧义。

**第 2 步，查题库。** 题库有两份，合并使用。一份是随仓库分发的 `answers.json`，194 道题，就是「题目 → 正确选项文字」的纯文本对照表，你可以直接打开看。另一份是只存在你电脑上的 `learned-answers.json`，记的是这个账号 **实际答对并到账过** 的题。本机这份优先，因为「在你账号上验证过」比「别人整理的快照」更可信。

匹配的原理见下图：先把题目和选项都做归一化（全角半角、空白统一），再按 **选项文字** 精确比对。不按 A/B/C/D 的位置，因为站点每天可能打乱选项顺序。必须 **恰好命中一个** 选项才算匹配。

![题库匹配：按选项文字比，不按 ABCD](docs/answer-matching.svg)

**题库没有怎么办？它不会瞎猜。** 直接标记 `answer_needed` 停下，结果里带上题目原文和全部选项。你查一次正确答案，用每日命令带上原题和正确选项的完整文字补答一次（写法见使用说明）。工具会先确认站点今天的题还是这道，再作答。也可以让 AI 助手查一次再填。

> 仓库题库里有少数题目记录的是多个候选答案，因为站点在不同日子给同一道题配过不同选项。这类题目当前不会自动命中，会走 `answer_needed` 让你确认一次；确认到账后就记进本机题库，以后自动命中。

**第 3 到 5 步，作答。** 点文字完全一致的选项按钮，点「提交答案」，然后等站点的答题接口真的返回（最多 45 秒）。

**第 6 步，核对到账。** 积分流水里当天有「每日答题 +1」，这一项才算 `reward_verified`。

**第 7 步，学习。** 这一步只在等到站点响应之后才做，因为只有那时才有可靠的证据。到账了就记为正确答案；站点显示已答却没到账说明答错了，把这个答案记进「错误名单」，以后拒绝再交，不重复扣米；没等到响应就什么都不记。

![答完之后学什么：只有到账才算证据](docs/answer-learning.svg)

## 5. 怎么判断「真的成功了」

很多脚本把「点到了按钮」或者「命令退出码是 0」当成功，结果按钮点了但站点没收到，第二天才发现断签了。这个工具不这样。

![怎么判断真的成功：四个条件和三种整体状态](docs/verify-flow.svg)

**每一项的判定。** 工具读积分流水接口返回的记录，逐条检查四个条件，全部满足才算 `reward_verified`：记录属于你的 uid；大米变动大于 0；标题正好是「签到奖励」或「每日答题」；时间折算成洛杉矶日期等于「今天」。缺任何一条都不算。

**整天的结论。** 综合两项动作的状态和奖励核对，按下面的决策树得出 `complete`、`needs_attention` 或 `failed`。`complete` 退出码 0，其余退出码 2，方便脚本判断。

![一天的结论是怎么算出来的](docs/status-decision.svg)

**每一项的状态** 也会单独给出：`already_done`（早就完成）、`reward_verified`（已到账）、`reward_unconfirmed`（完成了但没查到奖励）、`submission_unconfirmed`（提交了但没收到回执）、`answer_needed`（题库没题）、`not_done`（只读模式下还没做）。

**结果存在哪。** 全部在本机：数据库里一条一条记，另有一个 JSON 文件保存最近一次的完整原始结果。历史命令可以离线翻，还会给出一个健康判定。

![结果存在哪：全部在本机](docs/data-files.svg)

## 6. 失败重试：出错了它怎么自救

网络抖一下、Cloudflare 验证卡一下、电脑中途睡着、Chrome 崩了，这些都会发生。工具有六层保护，从秒级到天级，每层管一种时间尺度的问题。

![失败重试：六层保护](docs/retry-flow.svg)

| 层 | 尺度 | 做什么 |
|---|---|---|
| 1 | 秒 | 读接口或页面遇到网络超时，等 1 秒再读 1 次。只重读不重提交，因为读取没有副作用 |
| 2 | 秒 | 提交后最多等 45 秒站点的真实响应；快超时时自动尝试一次人机验证。没等到的记为 `submission_unconfirmed` |
| 3 | 分钟 | 一次运行最多 15 分钟。超时由一个独立线程从外部强制关掉 Chrome，记为 `daily_run_timeout`，历史照样保存 |
| 4 | 分钟 | 网络、验证、浏览器断开、看门狗超时这类错误，立刻换一个新 Chrome 再跑 1 次。重跑前先读本机历史和站点状态，已确认的动作不再做 |
| 5 | 小时 | 计划每 10 分钟触发一次；一天还铺了 6 个恢复时点（每 4 小时）。没到点、已完成就安静退出，所以重复触发是安全的 |
| 6 | 天 | 另配一个独立计划做健康检查：只读本机数据库，不开浏览器。连续 2 天没完成，或调度器 8 小时没心跳，返回退出码 3，你可以接桌面通知 |

这些数字都是 `settings.py` 里的常量，改一处全局生效。

**看一个具体的坏日子是怎么被接力救回来的：**

![一个坏日子的接力](docs/retry-timeline.svg)

**哪些错误会自动重试（第 4 层）：** 网络超时、网络不可用、页面或验证超时、Cloudflare 挑战没过、登录验证没过、浏览器连接断开、看门狗超时。

**哪些不盲目重试：** 密码错误、题库没题、按钮没点到。这些要么需要你处理，要么留给下一次计划自然再来。

### 提交发出去了，回执却没回来

这是最微妙的情况：按钮点了，请求发出去了，但 45 秒内站点没回应。工具不知道站点到底收没收到。重复提交可能被站点当成异常操作，不提交又会断签。所以规则是「有过回应就不重交；没回应最多补 3 次，每次都先查再交」：

![提交发出去了回执却没回来](docs/lost-submission.svg)

### 为什么第 6 层必须独立

一个进程发现不了自己没被触发：调度器坏了，主计划根本不会跑，也就不会报错。所以要有第二双眼睛在链路的另一端看着。健康观察者不碰账号、不开浏览器，只看本机数据库里「最近一次触发心跳是什么时候」「哪些天没完成」，给出 `ok`、`warn` 或 `alert`。

![健康观察者：第二双眼睛](docs/health-watch.svg)

## 7. 每天什么时候跑：调度

![调度：一天的时间线](docs/schedule-flow.svg)

- **计划时间** 默认 16:10（Asia/Shanghai）。在账号配置里加 `schedule_time` 和 `schedule_timezone` 就能改。不要改仓库里的 `settings.py`，那会让你的克隆和主分支分叉。
- **触发方式** 推荐每 10 分钟跑一次带 `--resume` 的每日命令。它自己判断该不该跑，没到点、已完成时直接退出、不开浏览器。
- **恢复时点** 是给「按固定时间点触发」的调度器准备的：从计划时间起每 4 小时一个。检查命令会打印本地时区和 UTC 两套时刻以及 rrule，照着填就行。
- **电脑睡着** 错过的触发，醒来后下一次检查会补上。只补「今天」，不补过去几天的签到。
- **心跳**：每次触发都在本机记一次，即使什么都没做。健康观察者靠它判断调度器还活着没有。
- **不要给同一个账号配两个调度器。** 浏览器有文件锁，第二个会直接报错。

### 站点的「一天」按洛杉矶时间算

这是很多签到脚本出错的地方：用电脑本地日期判断「今天签了没」，跨时区就乱。这个工具一律按站点所在的洛杉矶时间算站点日，奖励记录的时间戳也折算成洛杉矶日期再比较。

![站点的一天按洛杉矶时间算](docs/site-day.svg)

macOS 的 LaunchAgent 样例、Windows 任务计划程序的命令、健康观察者脚本，见 [使用说明 › 每日自动运行](outputs/一亩三分地本地工具/README.md#automation)。

## 8. 安全与隐私：你的数据在哪

![安全与隐私](docs/security.svg)

**密码。** 交互输入一次，macOS 存进登录钥匙串，Windows 用 DPAPI 加密。两者都和这台电脑、这个用户绑定，换电脑要重新配，拷密文没用。密码不进仓库、不进日志、不进 AI 助手的对话。整个流程见下图。

![账号和密码是怎么配置、怎么保存的](docs/password-flow.svg)

**登录会话。** 只存在专用 Chrome 的配置目录里。退出会话的命令只删这个目录里论坛域名的 Cookie，不碰别的。

**仓库里有什么。** `.gitignore` 是「默认全部忽略」的白名单，只有登记过的源码、题库、文档能入库。`work/` 整个目录永远不入库。检查命令还会扫描密钥特征（GitHub token、AWS key、私钥）和个人绝对路径，发现就失败。

**网络上只跟论坛自己的域名说话。** 专用浏览器只允许打开 `1point3acres.com` 及其登录、接口子域，别的地址在代码里直接拒绝。不经过任何第三方服务器，不用打码平台，不上传截图。

**它不会替你做的事。** 顶/踩、评分这类不可撤销或要花大米的操作，工具不做。发帖、回复、收藏、点赞这些互动命令默认只预览，加 `--submit` 才真正写站点，写完还会读回来核对。

## 9. 快速开始

![安装七步](docs/install-flow.svg)

### 最省事：交给 AI 助手

把仓库交给一个能在本机执行命令的 AI 编程助手（Claude Code、Codex 等），说「装好并配置每天自动签到答题」。它会完成克隆、建环境、装依赖、跑检查、部署每日计划。你只需要提供论坛用户名和数字 uid（个人空间链接里的 `uid=数字`），并在它弹出的安全输入框里输一次密码。密码直接进钥匙串 / DPAPI，助手不经手明文。

### 自己动手：七步的原理

前置：装好 Git、Chrome、Python 3.12。每一步的确切命令见 [使用说明 › 手动安装](outputs/一亩三分地本地工具/README.md#install)，这里只说每步在做什么、怎么算成功。

1. **克隆仓库。** 拿到源码。克隆本身不会创建任何计划，也不会碰站点。
2. **建虚拟环境、装依赖。** 在 `work/` 下建一个独立的 Python 环境，装 8 个锁定版本的库。不污染系统 Python。
3. **跑一次安装检查。** 检查命令带 `--sync` 会核对依赖版本、生成本机的 MCP 配置、跑离线测试，并启动一次临时 Chrome 验证阅读器。不登录、不签到。看到 `status=complete` 才继续。
4. **配账号、存密码。** 写一个只含用户名和 uid 的账号配置；然后在终端隐藏输入一次密码，交给系统保管。原理见 [安全](#安全) 那节的图。
5. **登录一次。** 会话命令用保管的密码建立登录。看到 `session_usable=true` 才算成功。不想存密码也可以微信扫码，但之后的日常自动恢复仍需要密码。
6. **手动跑一次签到答题。** 看到 `status=complete`。出现 `answer_needed` 就按 [答题](#答题) 那节补一次答案。
7. **配每日计划。** 让系统每 10 分钟跑一次带 `--resume` 的每日命令，从此不用管。再配一个健康观察者更稳。

<a id="测试"></a>

## 12. 质量保障：测试与 CI

![CI 流水线](docs/ci-flow.svg)

本地和 CI 跑的是同一个检查命令，输出一段 JSON，`status=complete` 才算过；有问题时 `violations` 列出每一条。它分三个阶段，可以只跑其中一个：

**静态检查看什么：** 每个模块只引用白名单里的模块；外部库只在登记的模块里引用；状态字段不许写字符串字面量，必须用契约模块里的枚举；数量上限这类默认值不许硬编码，必须来自配置模块；依赖清单和登记一致；MCP 工具名和登记一致；CSS 只能用视觉取值文件里的值；文档里的相对链接都存在；`git ls-files` 里没有未登记的文件，也没有登记了但不存在的文件；shell 入口带可执行位；没有二进制、密钥、个人路径。几秒钟跑完。

**单元测试看什么：** 每日流程的每个分支（已完成、没到点、题库没题、答错、提交丢失、重试一次、看门狗超时、站点日翻页……）、题库匹配、奖励核对、心情抽取、健康判定、凭据读写（macOS 上真实往返钥匙串）、命令行参数、MCP 参数守卫、面经解析、互动命令的先读后写。

**集成测试看什么：** 用 stdio 真实拉起 MCP 服务并握手；真实启动一次 Chrome 打开离线阅读器。不登录、不签到、不访问站点。

CI 在 Ubuntu、Windows 2022、Windows 2025、macOS 15 上分阶段跑，每个阶段都先重建生成文件再比对，生成物和源码不一致也算失败。Action 一律按 commit 哈希锁定，不用 secrets，不用自托管 runner。

## 13. 其他功能

这些都是可选的，不装不配也不影响签到答题。所有命令都在工具目录执行，全部输出 JSON，按用途分成六组：

![命令一览：按用途分组](docs/commands-map.svg)

**面经资料。** 采集指定公司的面经帖子（走站内搜索或公司标签页），存进本机数据库，导出成 JSON、CSV、Markdown 和一个离线阅读器；可以按关键词、岗位、级别、发帖日期搜索；帖子里的图片能归档到本机并做本机 OCR，识别文本和原文分开存放、分开标注。采集可以做成任务，支持暂停和从断点恢复。

**只读浏览。** 站内搜索、读帖、翻版面、看主页、读通知，都不入库、不标记已读。

**互动。** 发帖、回复、收藏、点赞。每个操作都是「目标状态」式的：先读现状，已经是目标状态就不提交；提交后再读回来核对，核对一致才报成功。默认只预览，加 `--submit` 才真正写站点。

**接给 AI 助手。** 工具同时是一个 MCP 服务，AI 客户端通过本机管道调用它，用的是和命令行完全相同的函数：

![接给 AI 助手：MCP 是怎么接的](docs/mcp-flow.svg)

每个命令的参数、返回字段、边界情况，见 [使用说明 › 命令参考](outputs/一亩三分地本地工具/README.md#commands) 和 [MCP 接入](outputs/一亩三分地本地工具/README.md#mcp)。

<a id="常见问题"></a>

## 14. 常见问题

看到一个错误码，先分清它是哪一类，大多数不需要你做任何事：

![看到一个错误码，先分清是哪一类](docs/troubleshooting-map.svg)

| 现象 | 原因 / 处理 |
|---|---|
| `not_due`、`already_complete`、`already_done` | 不是故障。还没到计划时间，或今天已经确认完成 |
| `answer_needed` | 题库没这道题，按 [答题](#答题) 补一次答案 |
| `account_not_configured` / `invalid_local_account_config` | 账号配置文件缺失或格式不对：UTF-8，只含用户名和 uid（可选计划时间和心情开关），uid 是正整数 |
| `login_required_credentials_not_configured` | 还没存密码，重做快速开始第 4 步 |
| `login_rejected` / `automatic_login_failed` | 核对账号密码和网站账号状态，不要连续重试同一密码 |
| `unexpected_account` | 浏览器里登录的不是配置里写的账号，工具拒绝操作 |
| `button_not_ready` / `page_challenge_not_resolved` | 页面没就绪或验证没过，本次保留失败，看下一次计划是否恢复 |
| `browser_connection_lost` / `daily_run_timeout` | 浏览器中途断开或超过 15 分钟（多为电脑睡眠），已自动重开一次；反复出现再看系统日志 |
| `another_task_is_using_the_browser` | 有别的任务在用浏览器，等它结束；确认没配两个调度器 |
| `consistency_check_failed` | 跑检查命令，按 `violations` 修；生成文件过期就加 `--sync` |
| 自动计划没跑 | 确认计划已启用、指向工具目录、电脑当时开着；跑一次历史命令看 `health` |

更多错误码和处理见 [使用说明 › 常见问题](outputs/一亩三分地本地工具/README.md#troubleshooting)。提 Issue 时给出系统 / Python / Chrome 版本、commit 短哈希、用到的命令和脱敏后的 `status` / `error`，不要贴账号配置或完整 JSON。

<a id="维护"></a>

## 15. 更新与维护

更新源码的原理是「先停、再拉、再检查、再开」：

![更新到新版本：五步](docs/update-flow.svg)

`work/` 目录里的账号、凭据、数据库、Chrome 配置都不受更新影响。计划时间之类的个人配置写在账号配置里，不改仓库里的 `settings.py`，更新时才不会冲突。具体命令见 [使用说明 › 更新与维护](outputs/一亩三分地本地工具/README.md#maintenance)。

**改代码：** 改完统一跑检查命令，先不带参数做完整离线检查与回归，再带 `--sync` 重建生成文件后再检查。新增模块、新增依赖、新增 MCP 工具、新增文件，都要同步登记到 `architecture.json`，否则检查会失败，这是故意的。

**几点须知：**

- 每位使用者配置自己的论坛账号，不会继承别人的登录、资料或每日计划；克隆本身不会创建计划，也不会执行任何网站操作。
- 读取内容以当前账号的权限为准。帖子详情或站内搜索返回结果，不等于已存进资料库。
- 已有实测不构成永久通过 Cloudflare 的保证；网站或验证变化可能导致某天失败，程序会如实记录。
- 本工具只用你自己的账号、在你自己的电脑上、按网页正常流程操作，请遵守论坛规则，自行承担使用风险。
